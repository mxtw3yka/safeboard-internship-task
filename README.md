# Safeboard — поиск уязвимостей

Консольный инструмент для поиска версий продукта, не попавших в интервалы уязвимостей, и просмотра сведений об уязвимостях для версии. Данные импортируются из двух JSON-фидов в PostgreSQL.

## Запуск

Нужны Docker и Docker Compose. Скопируйте шаблон в локальный игнорируемый файл и задайте в `.env` новое имя пользователя PostgreSQL и надёжный пароль; `POSTGRES_DB=safeboard` оставьте как в шаблоне:

```sh
cp .env.example .env
```

Проверьте Compose-конфигурацию без вывода значений окружения, затем соберите приложение:

```sh
docker compose config --quiet
docker compose build app
```

Разовый поиск безопасных по загруженным фидам версий Apache Tomcat:

```sh
docker compose run --rm app --versions /app/feed_task/versions.json --vulnerabilities /app/feed_task/vulnerabilities.json Apache Tomcat
```

Сведения об уязвимостях для версии (версия должна присутствовать в фиде версий):

```sh
docker compose run --rm app --versions /app/feed_task/versions.json --vulnerabilities /app/feed_task/vulnerabilities.json Apache Tomcat --version 9.0.85
```

Интерактивный режим:

```sh
docker compose run --rm app --repl --versions /app/feed_task/versions.json --vulnerabilities /app/feed_task/vulnerabilities.json
```

В приглашении `safeboard>`:

```text
safe Apache Tomcat
vulns apache tomcat 9.0.85
```

`safe` выводит найденные версии; `vulns` — совпавшие KLA ID, дату публикации и описание либо сообщение, что уязвимости не найдены. Для выхода нажмите Ctrl+C или отправьте EOF (Ctrl+D в Unix-подобной оболочке). Каталог `./feed_task` подключён в контейнер только для чтения как `/app/feed_task`. Имена файлов можно менять флагами `--versions` и `--vulnerabilities`, но альтернативные файлы должны находиться внутри подключённого каталога `/app/feed_task` (если не менять bind mount в Compose). Название продукта из нескольких слов, например `Apache Tomcat`, можно вводить без кавычек; пробелы разделяют аргументы, а программа объединяет их. Метасимволы оболочки в названии или пути (например, скобки) необходимо заключать в кавычки или экранировать на стороне оболочки.

## Логика и ограничения

Сопоставление продукта нечувствительно к регистру для передаваемых ASCII-названий. Версии сравниваются как числовые компоненты через точку; недостающие компоненты дополняются нулями. Интервал уязвимости — `[start_vuln_version, fixed_version)`: нижняя граница включается, исправленная версия исключается. Команда `safe` перечисляет только версии из фида версий, не покрытые ни одним интервалом для продукта; `vulns` показывает записи, чей интервал содержит указанную версию.

«Безопасная» здесь означает лишь отсутствие совпадения с диапазонами этих фидов при упрощённом глобальном числовом сравнении версий. Это не гарантия общей безопасности и не учитывает ветки продукта или иные источники сведений. Результаты зависят от предоставленных фидов.

## Обновление фидов и данные

Каждый запуск приложения заново загружает оба JSON-фида в выделенную базу PostgreSQL; замена данных выполняется в транзакции. В REPL файлы проверяются по хешам перед распознанными командами. При недоступном файле, синтаксически некорректном JSON или ошибке БД текущий запрос пропускается, последняя успешно загруженная пара данных сохраняется, а проверка повторится при следующей команде. Изменения не обнаруживаются, пока REPL ожидает ввод. Если два файла обновляются по отдельности, между ними возможен промежуточный набор данных: совместная атомарность изменений на стороне хоста не обеспечивается.

## Передача проекта

Для отправки задания создайте ZIP-архив с `tool.py`, `db.py`, `load.py`, `Dockerfile`, `compose.yaml`, `.dockerignore`, `.gitignore`, `requirements.txt`, `.env.example`, `README.md` и обоими файлами `feed_task/*.json`; назовите архив своим ФИО. Проверьте список файлов внутри архива: игнор-правила не фильтруют произвольную ZIP-упаковку, а `.dockerignore` исключает `.env` из контекста сборки образа. Не включайте локальный `.env`, `safeboard.db`, кэши, а также локальные артефакты Docker (образы и volumes).
